    How the network works

    The Railway control plane stores jobs and results. External workers connect by outbound HTTPS, announce exact capabilities, claim a leased job, and return its result. PostgreSQL and provider credentials are never given to workers.

    CONFIGURATION

    Keep keys and subscriptions on the worker

    Each operator chooses an allowlist of supported services. Ollama can run locally. OpenAI, Anthropic, DeepSeek and Higgsfield API credentials stay only in that worker's local environment file. Codex and Claude Code subscriptions are also supported through local CLI login with text.openai.codex and text.anthropic.claude-code; API-key capabilities remain available separately.

    Configuration reference ↗
    SECURITY

    No arbitrary remote code

    Prompts are data, not shell commands. Workers execute only approved adapters and workflows, use expiring lease tokens, and reject stale completions.

    Security model ↗
    RESEARCH PREVIEW

    Binance-aware agents, safely separated

    Future operators may contribute Binance-aware agents through local capabilities. The first proposed capability is public market data only. Account inspection would be a separate private, read-only opt-in; trading stays disabled until exact-order human approval, strict limits, audit logs and local credential custody are independently reviewed.

    Requester

    Can request an approved market-data task without owning a worker or receiving anyone's Binance credentials.

    Agent operator

    Runs the Binance skill locally, advertises only explicit capabilities, and retains every key on their own machine.
